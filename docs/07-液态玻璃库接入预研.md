## 目标

评估将 [QmDeve/AndroidLiquidGlassView](https://github.com/QmDeve/AndroidLiquidGlassView) 用于聊天输入栏背景的可行性，同时保持 Android 8.0（API 26）及以上设备可安装。液态折射效果需要 Android 13（API 33）及以上；较低版本继续使用现有 Haze 玻璃效果。

## 库与兼容性

- 上游组件：com.qmdeve.liquidglass:core:1.0.5，MIT License。
- 液态着色器使用 Android RuntimeShader / AGSL，因此完整效果需要 API 33+。
- 上游库的安装门槛低于本项目的 minSdk=26；API 33 是效果能力门槛，不是安装门槛，不需要提升 minSdk。
- Java 17、compileSdk 37 满足库的构建要求。
- API 33 以下、用户启用兼容模式或液态初始化/渲染失败时，沿用 Haze 玻璃路径。

## 采样结构与崩溃风险

液态库将采样源录制到 RenderNode，并用 AGSL 着色器处理采样纹理。曾发生 Recording currently in progress 崩溃：采样源绑定到包含液态表面的祖先 Compose 根节点；录制根节点触发 Compose 再布局，液态视图尺寸变化又启动嵌套录制。

因此不能绑定包含液态表面的祖先容器。聊天页采用隔离的 Android View 宿主，将聊天内容、玻璃表面和输入控件放在独立兄弟层：

```text
FrameLayout
├── ComposeView：聊天内容，作为采样源
├── LiquidGlassView：液态玻璃表面
└── ComposeView：输入控件
```

采样源不包含玻璃视图，玻璃视图也不处于采样源的布局子树中。此结构用于避免之前的重入路径。隔离原型的视觉效果已由用户确认；正式聊天页的页面生命周期和高频交互仍需真机压力验证。

## 设置与旧数据

输入栏背景类型保留 BLUR、旧序列化值 GLASS，并增加 LIQUID。旧 glass 配置在加载时归一化为 LIQUID 并开启兼容模式，维持原 Haze 观感；默认类型仍是 BLUR。兼容开关只在选择液态时可操作，其值在切换模式时保留。API 33 以下强制走兼容渲染。

## 异常保护

- 库的 RenderNode 录制有重入保护，并通过 finally 确保结束录制和清除录制状态。
- 初始化、尺寸变化、参数更新、绘制和 pre-draw 渲染失败都会记录异常。
- 渲染失败会触发进程级熔断，移除失效玻璃视图并改走 Haze；液态不能作为默认值。

异常保护只覆盖可捕获的运行时异常，无法替代设备验证，也不能证明不同 GPU、系统版本或长期高负载下没有图形驱动问题。
